2026-10-14，用户确认采用 A 方案，并继续审查整个仓库。保持 `.color('_brand')`、useCss、provideTheme、cx、bx 和不可变链的现有使用方式；本轮整理内部职责，不改变公共 API。

## 字面量方案的进一步简化

- 移除 keyword-views.ts、keywords.ts、仅供旧字典使用的 lazy 工具及对应专属测试，不保留兼容包装。生成器不再生成 camelCase 成员、系统引用或共享字典索引。
- 原生属性输入汇总命名为 PropertyValues；保留 literal-values.ts 的中文说明、原生值域和编辑器导航。metadata.ts 只保存共享 color 组适用的属性。
- theme.ts 在同一文件内直接查找主题组，保留目标属性优先、共享颜色回退、按需验证和引用身份复用。useCss/useTheme 共用注入记录；来源 WeakMap 不缓存当前主题值。
- useTheme 返回原始主题的 Readonly<Ref<T>>，首次读取 .value 才访问来源；不增加深层代理或隐式解包规则。需要持续读取映射值时使用 Vue computed 或 CSS bx。
- 迁移源码与发布类型夹具、区域/Teleport、HMR 输入和说明；保留 _missing、错误属性组、Ref 推断、泛型上界与只读入口的负例。

上一阶段 f53d88a 的 [完整 CI](https://github.com/kenconnet666/zerodep-vue/actions/runs/38588018777) 已成功。此阶段本地只做修改文件诊断与主题、编辑器和区域覆盖定点用例；完整矩阵由新提交 CI 验证。

## 实施顺序

1. CSS：作者类型集中到纯类型文件，运行时声明单独建模；运行时作者不再携带主题泛型。拆开嵌套代理中的完整职责，简化模板处理与 token 分派。保留主题名检查、Ref 推断、惰性求值、声明顺序、类名哈希和资源所有权。
2. 全仓手写代码：继续检查 core 的 TSX/开发工具、compiler 的变换/Vite/编辑器、语言服务/打包/生成脚本、UI 基础与 fixtures。优先消除重复策略和多层分支，不为了覆盖文件数量而制造改动。
3. 记录每块的结论、局部验证与对应 CI。新的公共 API 或需要改变既有语义的方向先讨论，不通过宽泛类型、删测试或兼容层掩盖问题。

## 整理准则

- 类型复杂度留在作者检查边界，运行时只处理值、声明与所有权。解释推断所需的交叉类型，不凭代数外观删约束。
- 一个判别值的多分支使用 switch；二选一、类型守卫和前提检查用 if/早返回。
- 提取能独立命名的完整职责，优先留在同一文件；不把几行逻辑拆成层层转发。
- 注释解释原因、求值时机和生命周期；类型文档配最小例子，维护者不必从生成文件猜契约。
- 固定上游源码与快照保留可对照性；生成文件只通过生成器更新。纯文档/声明数据不按手写算法的标准机械缩行。
- 本地只运行受影响文件诊断和少量短测，完整类型、浏览器、发布声明和全仓回归交给 CI。
