# 样式来源与运行检查

Vite 客户端开发模式自动接入 Vue DevTools，提供 **zerodep-vue CSS** inspector，并在 Vue 原有组件检查面板中补充当前样式。作者不用添加调试 props、手动登记组件或改变 class 写法。

检查面板读取当前 VNode 上已经完成的 CSS 解析结果，包括：

- 消费节点、所属组件 uid、实际类名和规则文本。
- 有序样式来源的文件、行、列及具名样式成员。
- 声明的目标、条件、有效值，以及生效、被覆盖、清除标记或当前省略状态。
- bx/主题绑定最近一次在该节点消费的值；被覆盖而没有消费的绑定明确显示未消费。
- 元素变量、动画资源与各帧声明，以及当前活动的全局规则。

定位指向作者 TSX：样式指向构造声明的位置，bx 指向传入的值表达式。未经过开发编译的外部声明仍可查看有效规则，但不能凭空补出源位置。普通第三方 CSS 的最终层叠继续使用浏览器原生检查工具。

检查是被动读取。重复打开节点、筛选树或刷新面板不会再次调用 getter，也不会为了猜测依赖而执行表达式。记录使用已求值的字符串/标量快照；对象型业务值不会被展开或执行字符串转换。动画和被覆盖声明也沿用同一边界。

节点快照与源码标记使用弱引用关联；inspector 只遍历当前组件树，不保留渲染历史。全局记录跟随实际租约释放，应用卸载后不再显示节点。客户端开发工具即使与 SSR 测试共处一个进程，也不会登记服务端请求的全局规则。

生产和 SSR 转换不生成源码标记或 DevTools 导入。生产浏览器构建还检查 chunk 模块清单，禁止把 DevTools/HMR 入口及记录表带入客户端或服务端产物。库自身为了检查上游 DevTools 声明而安装的 vue-router 仅是开发依赖，CSS 运行不要求使用路由。

CI 的开发工具任务运行真实 Vue DevTools 后端的注册、树查询和状态查询协议，核对行列位置、绑定读取次数、更新与释放；并独立保留源码映射测试，将开发、生产、SSR 中生成的事件处理代码映射回作者位置。浏览器扩展或面板的布局沿用 Vue DevTools，项目不建设另一套调试应用。
