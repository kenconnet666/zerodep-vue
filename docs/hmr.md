# Vite 开发更新

Vite 开发模式自动为自有组件建立渲染和样式更新边界，作者不用增加 hook 或改变组件写法。

| 修改                                                                 | 运行行为                                       |
| -------------------------------------------------------------------- | ---------------------------------------------- |
| 已有 `css`、`css.create`、`css.createTheme`、变量组或动画的声明内容  | 更新对应运行时描述，保留实例、Ref 和交互状态   |
| `_component` 返回区域中的文本、JSX、事件处理表达式                   | 用现有实例环境运行新的 render，保留 setup 状态 |
| setup 中 Ref 初始值、普通业务函数、props 元数据或其他初始化结构      | 使用 Vue HMR 重建组件                          |
| 普通 Vue `defineComponent`                                           | 沿用 Vue JSX 的组件重载路径                    |
| 无法独立移动的 `super`、`new.target`、直接 eval 或跨边界 await/yield | 保留原表达式，修改时走重建路径                 |

渲染函数和样式函数在编译时被分离，环境仍引用原实例中的真实变量。闭包变量读写、普通回调的 this、setup 中的快照值不会被改成另一套响应式语义。修改兼容的 render 可以开始使用同一 setup 中原本存在的变量；新增初始化状态会触发重建。

CSS 仍在运行时求值。热替换样式时只重算该段声明，普通 setup 样式读取不会因此成为永久响应式派生；`bx` 仍由实际消费元素读取。具名样式的解构、动画引用和变量引用保持可更新身份，样式宿主负责正常规则替换与租约释放。

组件中的 `css.global` 沿用组件作用域。可独立更新的样式模块中，模块级全局规则注册会复用原有所有者，声明变化原位更新；初始化结构变化、规则移除或模块 prune 时释放。带应用 mount 等顶层执行操作的入口交给 Vite 正常更新传播，不作为独立样式模块自接收。

语法错误由 Vite 显示源码位置；修复后重新接入原模块的数据和闭包。生产转换和 SSR 转换不插入 HMR 导入、函数表或实例环境。HMR 模块只在 `import.meta.hot.data` 中保存当前版本，使用 Vite dispose/prune 与 Vue 生命周期清理，不保存更新历史。

CI 的独立 Chromium/Firefox HMR 任务在生成副本中修改源码，保留原仓库文件。用例填写输入、打开真实 Naive Select 弹层，验证样式修改与 render 修改后的状态、事件行为、错误修复、连续 12 次规则变化的缓存上限、setup 变化后的重建及最终卸载。它与普通交互任务分开运行，语法错误测试不会干扰其他页面。

实现复用 [Vite HMR API](https://vite.dev/guide/api-hmr.html) 和 Vue 既有更新机制。准确的提交与测试证据见 [progress.md](progress.md)。
